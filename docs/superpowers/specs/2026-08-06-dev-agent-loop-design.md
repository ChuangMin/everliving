# 開發 agent 循環設計 — 想 / 寫 / 查 / 反思

**日期**:2026-08-06
**狀態**:設計已由人類逐節確認,尚未實作
**範圍**:**開發這個 repo 的 AI agent 分工**,不是遊戲世界裡的角色

---

## 一、要解的問題

人類提出兩個痛點:

1. **有些工作根本沒人做** —— 敘事/台詞/劇情、真模型驗證/playtest、美術/視覺資產、驗收/挑毛病,
   四塊都是順手做的,沒人專責,所以品質不穩
2. **一個 agent 一輪做太慢**

### 這套設計「不」解什麼(誠實記錄)

**它修不好「系統還是太簡單了」。** 人類 2026-08-06 實際打開來玩之後給的結論是那句話,
而四個 agent 更勤奮地轉,產出的是更多 code,不是更不簡單的遊戲。
能解那句話的只有人類自己的一句回答(見 `NOW.md`〈等人類決定〉)。

這一節留在設計文件裡,是為了讓之後任何 agent 讀到時知道:
**這個 loop 很忙,不等於專案在往驗證核心賭注的方向走。**

## 二、人類已裁定的事項

| 決定 | 內容 |
|---|---|
| 追蹤文件 | **新開 `LOOP.md`**,`NOW.md` / `TASKS.md` / `PROGRESS.md` 保持現狀不動 |
| 並行方式 | **輪流跑**,同一時間只有一個 agent 在動文件 |
| planner 能不能說「沒有」 | **不能**。每一輪都要交出東西(**推翻 `AGENTS.md` 第 25 行**,見第七節) |
| 反思頻率 | **每 3 輪跑一次** |
| 反思能不能刪 skill | **能**,但要寫理由 + 單獨 commit |
| 三個補丁 | 人類心跳、階 5-7 標記與配額、反思只准 append —— 全部採用 |

## 三、四個角色的契約

每個角色綁死一組**檔案所有權**。這是並行不撞車的機制,不是禮貌約定。

### 想 planner

- **只准寫** `LOOP.md` 的「排隊中」
- **只讀 code,不改**
- 每則任務必須帶**完成判準**(怎樣算做完,要能被 auditor 拿去對)
- 每則任務必須標**取材階數**(見第五節)
- **不准替人類拍板**:可以做卡住決定的**前置工作**,但不准代為決定。
  排階 5 的任務時要寫明「服務哪個卡住的題,而且兩條路都需要」

### 寫 builder

- **只准寫** `LOOP.md` 的「進行中」→「待驗收」
- **只准碰** `src/`、`static/`、`tests/`
- 一次只做一則。「退回重做」優先於「排隊中」
- **不准自己標 done**。做完移到「待驗收」,交棒給 auditor

### 查 auditor

- **只准寫** `LOOP.md` 的「驗收結果」、「退回重做」
- **只讀 code,不寫 code**。不准順手修、不准寫 feature
- 每則發現要附**證據**:`檔案:行號` 或指令輸出。沒有證據的意見不算發現
- 驗收通過的那一刻,**由它**同步回 `TASKS.md`(改狀態)、`PROGRESS.md`(append)、`NOW.md`(重寫)。
  它是最後一棒,所以三份舊文件永遠只有一個寫入者

### 反思 reflector

- **每 3 輪**跑一次(「輪次記錄」數到 3 觸發)
- **輸入**:那 3 輪的「驗收結果」與「退回重做」—— **失敗紀錄才是原料**
- **只准寫** `LOOP.md` 的「反思」、「skill 帳本」,以及 `AGENTS.md`(僅 append)、`.claude/skills/`
- **不准碰 `src/`**。它改的是「怎麼工作」,不是產品本身

產出分兩層,因為 `.claude/skills/` 只有 Claude Code 讀得到,而這個 repo 是多廠商協作:

| 產出 | 落在哪 | 為什麼 |
|---|---|---|
| 教訓 | `AGENTS.md`(append) | 跨廠商都讀得到,Codex/Qwen 那輪也學得到 |
| 新增/修改 skill | `.claude/skills/` | Claude Code 的便利包裝,照 `superpowers:writing-skills` 的格式 |
| 刪除 skill | 單獨 commit + 理由寫進 `LOOP.md` | git 可還原,所以放權 |

**四條硬規則**:

1. 同一個模式**出現 ≥2 次**才准寫成 skill。一次是意外,兩次才是模式
2. 網路抄回來的 skill 先標 `unverified`,**在一輪真實工作裡用過**才准轉正;
   沒用過的下次反思直接刪
3. 不准碰 `src/`
4. **不准刪 `superpowers:*`** —— 那是外掛,不是這個 repo 的東西

## 四、`LOOP.md` 結構

```markdown
# LOOP.md — 想 → 寫 → 查

**現在輪到**:寫(builder)   **上一棒**:想 @2026-08-06 14:20
**本輪次**:7   **距離下次反思**:2 輪   **距離人類心跳**:3 輪

## 退回重做      ← auditor 放,builder 優先撿
## 排隊中        ← planner 唯一能寫的區,每則標取材階數
## 進行中        ← builder,最多一則
## 待驗收        ← builder 交棒
## 驗收結果      ← auditor 唯一能寫的區,每則附證據
## 反思          ← reflector,每 3 輪 append 一則
## skill 帳本    ← 哪個 skill 何時建、驗證狀態、用過幾次
## 輪次記錄      ← 每輪 append 一行
```

**「現在輪到」是每個 agent 醒來讀的第一行。交棒就是改這一行。**
輪流跑,所以不會有兩個 agent 同時寫同一份檔案。

「skill 帳本」是刪除的依據:**三輪沒用過的 skill,反思那棒直接砍**,理由寫在旁邊。

## 五、planner 的七階取材梯

人類的指示是「就算沒 in-scope 也要生出東西做」。
所以真正要設計的不是「准不准說沒有」,而是**排隊空了的時候去哪裡挖**。

| 階 | 取材來源 | 標記 |
|---|---|---|
| 1 | `NOW.md`「下一個 loop 該做什麼」 | 免標 |
| 2 | `TASKS.md` 的 `todo` | 免標 |
| 3 | auditor 的「退回重做」 | 免標 |
| 4 | 收件匣裡還沒排進去的 | 免標 |
| 5 | **繞過阻塞**:卡住的決定**兩條路都需要**的共同前置 | **要標** |
| 6 | 降債:測試覆蓋、真模型驗證、文件跟 code 對不對得上 | **要標** |
| 7 | **把決定變便宜**:做出可比較的原型,讓人類打開就能指 | **要標** |

**階 5 的例子**:「雙角色 vs 純化身」還沒定,但兩條路**都需要** profile 存取層、
都需要臉/身體/聲音的資料模型。那些現在就能做,做完不管人類選哪邊都不浪費。

**階 7 的例子**:「系統還是太簡單了」人類答不出來,很可能是因為憑空描述太難。
planner 可以排「做兩三個對照版本」,讓他打開直接指哪個對。

**注意**:階 5-7 是**無底的** —— 測試覆蓋永遠不夠、原型永遠可以再做一個。
所以第六節的補丁 2 對它們設了配額。

## 六、三個補丁

這三條是為了擋住第八節列的風險,不是可選的裝飾。

### 補丁 1:人類心跳

**每 N 輪(預設 5),loop 必須產出一個人類打開來看的東西** —— 不是報告,是能跑的畫面。
**人類沒開,loop 就暫停。**

為什麼:auditor 驗收的是自己隊伍的產出,沒有外部錨,標準會隨輪次軟化。
唯一真正的錨是人類實際打開來玩。這條同時也把 `NOW.md` 裡卡著的 H-1 playtest 逼出來。

### 補丁 2:階 5-7 要標記且有配額

planner 每輪排 **2-4 則**,每則標取材階數。**同一輪排的任務裡,階 5-7 不得超過半數**
(排 2 則最多 1 則、排 3-4 則最多 2 則)。

為什麼:階 5-7 每則都有像樣的理由,所以爛工作會變得**更難**被看出來,不是更容易。
標記讓人類掃一眼就知道「這輪四則有三則是 agent 自己想出來的」。

### 補丁 3:反思只准 append 到 `AGENTS.md`

reflector **不准修改 `AGENTS.md` 已經存在的行**。要改就寫成提案,放進 `LOOP.md` 的「反思」等人類點頭。

為什麼:反思能改另外三個角色遵守的規則,那是自我修改迴路。
git 是能還原,但沒有人會去讀第 40 個 `AGENTS.md` diff。
規則會朝「對 loop 方便」的方向漂,而不是朝人類當初寫下的方向。

## 七、連帶要改的 `AGENTS.md`

**`AGENTS.md` 第 25 行「『今天沒有事該做』是一個正確的結果,而且經常會是正確的結果」
跟這個設計直接矛盾**,必須改寫,否則下一個 agent 會讀到兩份打架的指令。

保留原本那條規則的**用意**——擋住「為了填滿 session 而發明任務」——
但把實現方式從「允許回報沒有」換成「**七階取材梯 + 階 5-7 標記與配額**」。
規則的目的沒變,機制換了。定稿如下:

> ## 最重要的一條規則
>
> **每一輪都要交出東西,但每一則都要說得出它是從哪裡來的。**
>
> 這個專案曾經靠「沒事做就停下來」來擋住技術債(舊版規則)。
> 現在改成靠**取材階梯**擋:planner 從第一階開始往下找,找到就停,
> 用到第 5-7 階的任務必須標記,而且一輪內不得超過半數(見設計文件第五、六節)。
>
> 擋的東西沒變:**為了填滿輪次而發明的任務,會製造技術債並把專案推往還沒被驗證的方向。**
> 標記就是為了讓這種任務**看得見**——人類掃一眼就知道這一輪有幾則是 agent 自己想出來的。
>
> 唯一不准的仍然是:**替人類拍板**。卡住的決定可以做前置工作,不能代為決定。

`AGENTS.md`〈兩種角色〉那節也要從 planner/builder 兩種擴成四種,並指向 `LOOP.md`。

## 八、已知風險(不解決,只記錄)

1. **這套東西修不好「系統還是太簡單了」**(見第一節)。蓋一座四人工廠,
   很可能是在真正的阻塞旁邊找事做的高級版本
2. **階 5-7 無底**,loop 永遠不會閒下來,但會慢慢漂向沒人要的工作。補丁 2 只是讓漂移可見,不是擋住它
3. **auditor 沒有外部錨**,標準會軟化。補丁 1 是唯一的對策,而它依賴人類真的去開
4. **反思是自我修改迴路**。補丁 3 把它降級成提案制
5. **成本**:四個角色輪轉會燒 token,而這個專案的驗證關卡是「一個人類打開來玩」

## 九、不做什麼(YAGNI)

- **不做並行**。人類選了輪流。瓶頸從來不是吞吐量,並行只換來 merge 衝突
- **不做 `.claude/agents/` 以外的編排工具**。角色契約的權威來源是 `AGENTS.md` + `LOOP.md`,
  `.claude/agents/` 只是 Claude Code 的薄包裝,指回去,不重複維護第二份
- **不合併 `NOW.md` / `TASKS.md` / `PROGRESS.md`**。三份的性質不同
  (整份重寫 / 看板 / append-only 歷史),硬合會打架
- **不做跨廠商的執行器**。其他廠商的 agent 讀 `AGENTS.md` + `LOOP.md` 就能扮演任一角色,
  不需要工具支援
