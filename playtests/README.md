# playtests/ — 跑過的紀錄

一次 playtest 跑完就只剩人的印象,而印象會變。這裡放**當時真的印出來的東西**,
所以之後討論「那次到底長什麼樣」時有原文可看,不是靠回憶。

檔名是 `<日期>-<跑的是什麼>.txt`。

- `2026-08-05-h1-autoplay.txt` — H-1 五步流程用 **AI 代打**跑的排練
  (`python tools/h1_autoplay.py`,provider=groq / `qwen/qwen3.6-27b`)。
  **這不是 H-1 的答案**:H-1 問的是「**你**想不想再打開」,agent 說它覺得有趣不算數。
  它驗的是流程通不通、狀態與懸念有沒有跨 session 接起來、以及四步花多少 token。
- `2026-08-05-refusal-check.txt` — 委託的**拒絕**路徑(第十二節那兩條規則)。
  灌一個會頂撞差事的狀態(手傷 + 對機器廠的積怨)再委託他去扛重物。
  **3/3 拒絕,而且每一次的理由都同時抓住兩個狀態**,讀起來像角色不像系統失敗。
  **同時抓到我自己的 prompt bug**:沒有既有懸念時,「通常要留下一件懸念」那條會跟
  「拒絕本身就是懸念」打架,模型兩條都聽 → 產生兩條同義的懸念。
  修好後重跑 **2/2 只剩一條**(第 3 次撞到 Groq 每日額度上限)。
- `2026-08-05-delegation-check.txt` — 委託機制(T1-C1)接上真模型跑一遍:
  玩家請他去回收場找壓力閥 → 他把它記成一句自己的話 → 隔天的離線敘事把它結掉。
  **順便撞上了別的事**(廢料堆塌陷、掀開一個在漏水的配電艙門),
  那正是設計文件第十二節說「委託模式白送的」那個落差。
  **沒驗到的是拒絕路徑**——這一次他答應了。
- `2026-08-05-t0-17-check.txt` — T0-17 改完 prompt 之後,拿上面那次跑完的 DB
  (結尾有兩條幾乎一樣的懸念)重跑三次離線模擬,每次一個 LLM 呼叫。
  **3/3 不再開重複的那一條;但只有 1/3 真的把舊的標成 resolved**——
  另外兩次模型其實有道理:軸承還沒送到,那條懸念本來就沒結束(細節見 T0-18)。
